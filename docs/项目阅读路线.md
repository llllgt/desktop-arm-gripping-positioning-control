# 项目阅读路线

先看 `results/native/demo.mp4` 和 `cad/generated/engineering_drawing.pdf`，理解工件在哪里、夹指为什么能进入托座、结构附件起什么作用。再按下面的顺序阅读。

## 1. 从机械任务开始

打开 `config/task.json`、`cad/design.json` 和 `docs/设计说明.md`。核对工件尺寸、托座支承宽度、夹指厚度、抬升净空和新增质量。观察托座比工件窄的原因：夹指需要从两侧进入，宽支承会干涉。

自己改一个参数，例如工件质量 30 g → 40 g，输出到新目录运行一次，比较放置偏差和关节力矩。不要覆盖默认实验记录。

## 2. 搞懂四轴能做什么

读 `desktop_arm/kinematics.py`。沿底座、肩、肘、腕、工具顺序画出坐标。跟着正解算一个姿态，再看逆解如何化成径向平面的两连杆问题、如何筛选肘部解和关节范围。

你应能解释：为什么四轴不能任意控制位置加三维姿态；为什么完全垂直朝下的工具在抬升点可能超过腕关节范围；不可达目标如何被拒绝。

## 3. 理解轨迹与结构的关系

读 `trajectory.py`、`task.py`。画出三次和五次时间缩放的速度、加速度曲线。注意五次轨迹段端加速度为零，但这不自动保证更低的放置误差。理解速度、加速度、执行器饱和和工件滑移各自影响什么。

状态顺序不是简单两点连线：先到上方、下探、夹紧等待、抬升、转移、下放、松开等待、撤离。能够解释每一个等待和净空的用途。

## 4. 看真实接触如何工作

读 `scene.py` 与 `simulation.py`。找到工件自由关节、接触垫、摩擦、驱动力上限和重力补偿。观察重力补偿通过执行器目标偏置实现，总力矩仍受限制。

运行 `scripts/benchmark.py` 后看对照。你应能解释：去附件实验为何不能证明胜过真实原装夹指；合成的十组扰动为何不能写成实机成功率。

## 5. ROS 是怎么串起来的

读 `ros_nodes.py`，找到任务客户端、两个 action 服务、状态反馈和结果保存。用 `scripts/run_ros.ps1` 在本机复现双进程实验。检查 `results/ros2/task.log` 中状态顺序和 `action_checks.json` 中取消验证。

理解本项目是自写的仿真控制桥，知道 ros2_control、MoveIt、Gazebo 在此并未集成。能画出“任务 → action → 控制器 → MuJoCo → 状态反馈”的数据流。

## 6. 核对力学结论

读 `structure.py` 与实验记录。手算悬臂梁挠度和夹持摩擦需求，再和数值结果比较。说明全固定边界为何不代表胶粘、线性四面体为何可能偏硬、TPU 为何不能直接套用铝背板的小变形模型。

## 写进简历前

仓库由 AI 辅助实现，个人经历应体现你实际完成的学习、复现、修改和判断。至少亲自运行一次、解释参数和限制，并做一次有记录的改动。不要写“整机自主设计”“实机调试”“工业级精度”或未经完成的加工装配。

可采用的客观项目表述：

> 桌面机械臂工件搬运系统：基于 OpenMANIPULATOR-X 开展夹指附件与定位托座的参数化设计，结合四轴运动学、五次关节轨迹与 ROS 2 action 控制完成搬运仿真；通过梁理论/有限元及接触实验核对结构和运动方案。

将表述中的个人动作调整为你真正做过、能现场解释的内容；仿真指标单独注明验证条件。
